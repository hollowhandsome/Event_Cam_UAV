# DVSLume 事件检测、回放与网口转发程序（Windows x64）

本程序支持连接一台或两台 DVSLume 事件相机，经 UDP/IPv4 向总体上位机发送 UEVT V1
数据包。程序已经编译，不需要 Python、编译器或源代码。提供两种网口转发模式、
单相机双视图、双相机四画面和 RAW 文件回放：

- **UAV 筛选事件转发**：运行检测、跟踪和分类，只发送 UAV 目标框内事件；
- **原始事件转发**：绕过检测模型，发送 DVSense SDK 输出的全部 Event2D 事件。
- **原始/滤波双视图**：左侧显示全部 Event2D，右侧只显示最终分类为 UAV 的事件。
- **RAW 文件双视图回放**：不连接相机，从厂家 RAW 文件运行同一套检测、跟踪、分类和滤波流程。
- **双相机/双 RAW 四画面**：两路输入按列排列，上排原始事件流，下排 UAV 滤波后事件流。

这里的“原始事件”是相机 SDK 解码后的坐标、微秒时间戳和极性，不是厂商 RAW 文件字节流。

## 1. 使用前准备

1. 使用 64 位 Windows 10/11 电脑。
2. 安装厂家提供的 Windows x64 DVSense SDK/驱动，默认目录应为
   `C:\Program Files (x86)\DvsenseDriver`。
3. 实时模式需连接 DVSLume 相机，并关闭 DVSense Viewer 等正在占用相机的软件；RAW 回放不要求连接相机。
4. 使用网线连接总体上位机，确保两端 IPv4 地址互通。
5. 双击 `检查运行环境.cmd`，全部显示“通过”后再启动。

实时相机模式会读取 `config\camera.ini`，设置 Bias 后立即回读校验。回读不一致时
程序会报错退出，不会带着错误 Bias 继续运行。

## 2. 修改实时相机 Bias

先关闭所有实时相机程序，再用记事本打开 `config\camera.ini`：

```ini
bias_diff_off=90
bias_diff_on=45
```

将等号右侧改为需要的非负整数并保存。实时双视图、UAV 筛选转发和原始事件转发
共用这一份配置。程序启动输出会显示 Bias 回读值；如数值超出当前 SDK/固件支持范围，
设置或回读校验会失败。不要在等号后面写行内注释。

RAW 文件回放不读取 `camera.ini`：其 Bias 在录制时已经确定，回放阶段无法修改。

## 3. 双相机和双 RAW 四画面

双 RAW 测试不需要连接相机。双击 `启动_双RAW四画面回放.cmd`，依次输入两个不同的
`.raw` 文件和播放倍率。四画面固定为：

| 位置 | 内容 |
|---|---|
| 左上 | RAW/相机 1 原始事件流 |
| 右上 | RAW/相机 2 原始事件流 |
| 左下 | RAW/相机 1 UAV 滤波后事件流 |
| 右下 | RAW/相机 2 UAV 滤波后事件流 |

两份 RAW 分别以自己的起始时间为零点，并按相同的 20 ms 时间步同步推进。较短文件
先结束后保持最后画面，另一份继续播放；两份都结束后窗口保持打开。

四画面窗口使用离屏双缓冲并一次性刷新，已消除原先逐块清屏、绘制导致的明显闪烁。
青色标题表示原始事件流，绿色标题表示 UAV 滤波后事件流；图像保持相机原始宽高比，
多余区域以深色留边。此显示优化不改变检测、跟踪、分类或网口转发数据。

连接两台相机前，先从 DVSense 官方工具取得两台相机的序列号，然后分别编辑
`config\camera1.ini` 和 `config\camera2.ini`：

```ini
serial=实际相机序列号
bias_diff_off=90
bias_diff_on=45
```

两个序列号必须存在且不能相同。配置完成后双击 `启动_双相机四画面.cmd`。如果还要
转发两路 UAV 滤波事件，双击 `启动_双相机四画面并转发.cmd`：相机 1 默认发往
`192.168.31.100:50000`，相机 2 默认发往 `192.168.31.100:50001`。需要更改地址时，
编辑 `tools\start_dual_live.ps1` 顶部参数默认值，或者从 PowerShell 显式传参。

双相机模式为两路输入分别建立队列、检测器、跟踪器、分类器和滤波器，不会混用轨迹。
相机通常由进程独占，因此不要再并行启动其他相机程序。

## 4. 设置上位机地址

用记事本打开需要运行模式对应的配置文件：

- UAV 筛选模式：`config\filtered.ini`
- 原始事件模式：`config\raw.ini`

把 `destination_ip` 改为总体上位机网卡的实际 IPv4 地址；双方约定其他端口时再修改
`destination_port`。默认端口为 50000。不要修改 `mode`，也不要在配置中增加未知字段。

筛选模式模型默认阈值由模型文件固化为 **0.24**。该模型不使用焦距和距离输入。

## 5. 启动和停止

- 双击 `启动_UAV滤波事件转发.cmd`，启动筛选模式；
- 双击 `启动_原始事件转发.cmd`，启动全事件模式；
- 双击 `启动_原始与滤波双视图.cmd`，打开左右对比窗口；
- 双击 `启动_RAW文件双视图回放.cmd`，输入 RAW 文件路径和播放倍率；也可将 `.raw` 文件直接拖到该脚本上；
- 双击 `启动_双RAW四画面回放.cmd`，使用两个不同 RAW 文件验证四画面；
- 双击 `启动_双相机四画面.cmd`，同时查看两台已配置序列号的相机；
- 双击 `启动_双相机四画面并转发.cmd`，在四画面显示的同时分别向 50000/50001 端口转发；
- 在运行窗口按 `Ctrl+C` 安全停止。

双视图和四画面窗口使用 `Q` 或 `Esc` 退出。界面只绘制已经得到最终分类结果的有效
轨迹：红色 `drone` 和蓝色 `non-drone`，并保留轨迹号及两位小数概率。尚未形成有效
轨迹或尚未最终分类的 `activity`、`motion` 候选不显示。滤波画面为空表示当前没有
目标被最终分类为 UAV，并不表示相机没有事件。

检测标签采用透明背景，避免覆盖事件图像。ON/正事件为亮青色，OFF/负事件为亮橙色；
每次刷新只显示当前 20 ms 事件窗口，上一窗口未再次触发的像素立即恢复灰色，因此不会
通过渐变累积形成拖影。该显示规则不改变检测、分类、滤波和 UEVT V1 网口数据。

RAW 回放倍率必须大于 0 且不超过 16，默认为 `1` 倍实时速度。文件播放完成后窗口会保留
最后画面，直到用户按 `Q`、`Esc` 或关闭窗口。RAW 文件由已安装的 DVSense SDK 解码，
因此即使不连接相机，也仍需安装厂家 SDK。
回放时的 Bias 由 RAW 录制时的相机设置决定，回放阶段不会也不能将其重新设置为 90/45。
当前厂家 SDK 接口使用窄字符文件名；如脚本提示路径字符不受系统 ANSI 代码页支持，
请把 RAW 文件移到纯英文/数字路径后再回放。

除专用双相机程序外，不要同时启动多个实时脚本：一台相机通常只能由一个进程独占打开。

### RAW 回放实测

使用 `50 270.raw` 和包内无焦距/距离依赖模型实测：在 RAW 时间 2.96/3.15 s 处累计处理
107,984 个事件和 149 个时间窗，当前识别到 2 个目标，其中 `drone` 概率为 0.30，
高于模型内置阈值 0.24，当前累计 42 个 UAV 滤波事件，单窗口处理耗时 2.58 ms。
原始事件画面可标注 `drone` 和 `non-drone` 有效轨迹，滤波画面仅保留 `drone`；未分类
的 `activity`、`motion` 候选不绘制。验证截图位于
`docs\RAW双视图回放验证.png`。

双 RAW 四画面已使用 `50 270.raw` 和 `35 500.raw` 在 16 倍速下实测。两路分别播放
至 3.15 s 和 14.90 s，累计处理 108,660 和 1,453,817 个事件，无标准错误；完整
回放前后进程 GDI 对象数均为 16，未发现绘图资源泄漏。双缓冲美化版验证截图位于
`docs\双RAW四画面回放验证.png`。

网口转发模式的启动首行会显示相机型号、序列号、分辨率、Bias 回读值、模式和目标地址。之后每秒显示：

- `input_eps`：相机输入事件/秒；
- `sent_eps`：已发送事件/秒；
- `packets_s`：UDP 包/秒；
- `mbps`：UEVT UDP 负载速率；
- `queue`：等待发送的窗口数；
- `camera_drops`：相机回调队列丢弃批次数；
- `dropped_windows`、`dropped_events`：网络队列丢弃量；
- `send_errors`：UDP 发送错误数。

上述丢弃量和错误应长期为 0。原始模式数据量显著更大，采用尽力发送，不会静默抽样；
如果持续出现丢弃，应先检查网口速率、上位机处理能力和局域网拥塞。

## 6. 网口数据协议、上位机和防火墙

单相机时上位机监听 `0.0.0.0:50000`。双相机时同时监听 50000 和 50001，并在
Windows 防火墙中允许对应 UDP 端口入站。UEVT V1 数据格式不变，上位机按接收端口
区分相机来源。
运行包根目录的 `网口转发数据协议_UEVT_V1.md` 是完整协议文档，可直接交给总体上位机
开发人员。UEVT V1 每个 UDP 负载不超过 1472 字节，固定包头 48 字节，每条事件
12 字节，多字节整数为网络字节序（大端），负载使用 IEEE CRC-32 校验。

Python 接收/解码示例、公开 C 头文件和两种模式的二进制/PCAP 样例位于
`integration` 文件夹。其中 `integration\python\uav_event_receiver.py` 可用于上位机联调。

协议 `flags`：bit0（0x0001）表示筛选模式的前回溯数据；bit1（0x0002）表示原始事件模式。

## 7. 常见问题

- **No available DVSLume camera was found**：检查 USB、驱动，关闭其他相机程序后重插相机。
- **DVSLume serial ... was not found**：检查 `camera1.ini`/`camera2.ini` 中的序列号和 USB 连接。
- **Dual-camera serials must be different**：两份相机配置误填了同一个序列号。
- **Failed to set/read back bias**：SDK/固件不支持当前参数或相机通信异常，重新连接后再试。
- **Failed to open camera config**：检查 `config\camera.ini` 是否存在，且启动脚本和目录结构未被改动。
- **Camera config is missing/invalid**：`camera.ini` 必须同时包含两个 Bias 键，键名不能重复或修改。
- **Failed to open runtime config**：不要移动 `bin`、`config`、`models` 的相对目录。
- **RAW 文件不存在**：建议把 `.raw` 文件直接拖到 RAW 回放脚本上，避免含空格的路径被错误拆分。
- **RAW 路径字符不受支持**：厂家 SDK 的当前接口受 Windows ANSI 代码页限制，请把文件移到纯英文/数字路径。
- **UDP destination must be an IPv4 address**：`destination_ip` 必须是点分十进制 IPv4。
- **上位机收不到数据**：检查 IP、UDP 端口、防火墙和网卡路由；筛选模式只有判定为 UAV
  后才发送事件，排查网络时可先用原始模式。
- **原始模式大量丢包**：确认链路至少为千兆以太网，并增大上位机 socket 接收缓冲区。

## 8. 完整性校验

`SHA256SUMS.txt` 列出包内文件哈希。PowerShell 可使用
`Get-FileHash -Algorithm SHA256 <文件路径>` 复核。程序包未包含 DVSense 厂商 DLL，使用的是
本机正式安装的 SDK。

## 9. 同机版 C++/C# 上位机

新增的 `upper_host` 目录面向相机和上位机运行在同一台 Windows x64 电脑的部署方式：

- C++ `EventCore.dll` 直接调用 DVSense SDK，并使用 OpenCV `cv::Mat` 独立管理最多 20 路相机事件、成帧和参数读写；
- C# WPF 以 5 行 × 4 列显示 10 组宽/窄视场共 20 路画面，默认适配 1280×720，支持单路放大、Bias 配置和单路/批量启停；
- C# 与 C++ 通过 P/Invoke 在本机进程内通信，不经过 UEVT/UDP。

安装 MSVC C++ Build Tools 后，依次双击 `构建_同机上位机.cmd` 和
`启动_同机相机上位机.cmd`。详细说明见 `upper_host\README.md`。新增文件不在原始运行包的
`SHA256SUMS.txt` 清单中；该清单仍用于核验原有相机端程序文件。
